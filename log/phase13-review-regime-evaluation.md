# Phase 13 regime and evaluation review — 2026-09-23

Goal reviewed: causal BTC regime gating and a reproducible, bounded forward evaluation without changing historical replay unexpectedly. I traced the CLI → experiment → probability cache → replay path and the bot startup → cycle → aggregator path. The smallest corrective approach is to retain each label's actual future timestamp and validate that timestamp at each training boundary; a fixed clock-hour subtraction cannot prove a row-shifted label is available on sparse data.

## Blocking findings

1. **Sparse feature rows leak future labels into a walk-forward fit** (`backtest/signal_cache.py:65-67, 147-155`; also the uncached training path in `backtest/engine.py:240-252`). `future_close` is the eighth *subsequent row*, but the training mask assumes it is available eight clock hours later. Reproduction: feature timestamps `2026-01-01 00:00` through `07:00`, followed by `2026-01-02 01:00`; set that final close to 200 and prior closes to 100. At the retrain on `2026-01-02 00:00`, the mask's cutoff is `2026-01-01 16:00`, so the first row is passed to `train_walk_forward` with a label derived from the *future* 01:00 close. I executed this synthetic sequence against `precompute_walk_forward_probs` with a capturing trainer and observed the `(Jan 1 00:00, future_close=200)` row in its training frame. Persist each label's matched future timestamp and require `future_timestamp < retrain_timestamp` (or the chosen strict availability boundary) in both cache and direct training paths. Add a gappy-data regression.

2. **Probability cache identity omits the raw bar stream that controls retraining** (`backtest/experiment.py:121-149`; `backtest/run_backtest.py:77-111`). The key hashes feature rows and schedule parameters, while `precompute_walk_forward_probs` sets its first and later retrain boundaries from `bar_stream` (`backtest/signal_cache.py:142-161`). Repairing, inserting, or removing an OHLCV bar can shift those boundaries without changing the feature-table fingerprint. In that case `resolve_prob_cache` at `backtest/experiment.py:133-136` returns probabilities from the old schedule and does not rebuild. Example: inserting one earlier raw bar moves the first `min_train_days` boundary back one hour or day while the current key is unchanged. Include an OHLCV/bar-timestamp fingerprint and cache algorithm version in the key, validate metadata on load, and cover a raw-only correction. The algorithm version is also needed when the label-availability fix changes probability generation but source rows remain identical.

## Important findings

3. **A regime refresh failure during startup prevents the bot from managing existing positions** (`execution/bot_runner.py:282-284, 298-309`). `resolve_regime` runs before the `try` and before `run_once`, where refresh exceptions are handled correctly at lines 139-147. If the BTC database query raises on restart, the process exits before `close_expired_positions` can run; a persisted paper position therefore misses its time stop. Start with an enabled but unavailable regime map plus `refresh_failed`, then let the first cycle attempt refresh and continue exits. Add a startup-failure test; the current tests cover failure only inside `run_once`.

4. **The regime block diagnostic reports zero when all scored days lack a classification** (`backtest/experiment.py:315-319`; `signals/regime.py:243-249`). `scored_regime` contains only days present in the regime map, and `days_blocked_pct({})` returns `0.0`. For a short history, a 200-day warm-up after a BTC gap, or any period with missing BTC data, every candidate BUY is blocked but `metrics.json` says `regime_days_blocked_pct: 0.0`. Report unavailable days separately and calculate blocked/unavailable rates over the replay dates, while preserving the existing RISK_OFF-only metric name if downstream users rely on it.

## Verified paths and limits

- `build_causal_regime` requires 24 distinct valid UTC hourly closes and maps the resulting state to the following UTC day (`signals/regime.py:187-240`). Both live and replay call `regime_decision`, which blocks BUY on absent/invalid state and leaves SELL available (`signals/aggregator.py:134-149`; `backtest/signal_cache.py:251-259`). The runner marks and clears `refresh_failed` after each cycle refresh (`execution/bot_runner.py:139-147`).
- Paper quote client construction uses public mainnet (`execution/bot_runner.py:56-58, 282`), matching the mainnet candle source.
- Explicit evaluation bounds are normalized to UTC and applied as `[start, end)` to replay bars while full history remains available to cache/regime preparation (`backtest/experiment.py:79-90, 275-329`). The artifact records the interval.
- Focused non-golden tests: **108 passed, 1 deselected** using a unique temporary pytest directory. Golden parity was deselected; this review does not claim a golden replay pass. No database or exchange operation was run for this review.

Verdict: **fix then validate the corrected baseline**. The sparse-row label leak can contaminate the model fit, and the unchanged cache key can silently reuse prior probabilities after repairing the data or algorithm.
