## Implemented in this session

### Causal regime and runner changes

`signals/regime.py` adds `build_causal_regime(bars, candidate)` and a shared
`regime_decision` rule. Classification from a complete UTC day is used on the
following entry date. R1/R2/R4 require 200 consecutive complete days; R3 requires
60. A complete day has 24 distinct hourly candles with finite positive closes.
Missing/invalid days reset warm-up. Enabled but unavailable regime blocks BUY;
`None` means deliberately disabled.

Live/replay aggregation use that rule. Runner refresh errors block entries and
can recover, while SELL and position exits continue during ordinary cycles.
Regime state/source date/reason enter decision history. Paper quotes use public
mainnet data; live keeps its configured client. **Startup error handling remains
part of unfinished review fixes below.**

Report: `log/phase13-regime-report.md`.

### Completed candles and validated hourly refresh

REST ingestion filters unfinished candles, overlaps incremental fetches,
updates existing candle values, guards cursor progress, and propagates symbol
failures. The old independent `airflow/dags/dbt_features_dag.py` is deleted.
The replacement `ohlcv_feature_refresh` DAG is hourly with one active run.

`ingestion/feature_validation.py` implements a PostgreSQL session advisory lock,
generation tokens, invalidation before refresh, and publication only after dbt
tests succeed. The current DAG uses one PythonOperator to hold the lock across
invalidation → backfill → dbt deps/build → publication. `cli features` follows
the same publication protocol. Standalone backfill invalidates publication.

`execution/freshness.py` requires valid publication for the current feature
timestamp. Missing state fails closed. The lightweight validation engine builder
is in ingestion so it is importable by the Airflow image, which does not mount
the backtest/signals packages. It now calls `load_dotenv()` before reading env.

This agent was interrupted before writing its report/final handoff. Current
implementation is on disk; inspect it rather than starting over.

### Experiment windows, caching, and dashboard

`cli experiment` / `ExperimentConfig` accept paired aware `--start` and `--end`
timestamps, normalize UTC, and score `[start, end)`. Full earlier training and
regime history is retained; only replay bars are filtered, because the underlying
engine previously ignored its config bounds. Artifacts store the declared range.
The dashboard now uses those bounds even for no-trade runs, with legacy fallback.

`backtest/data_store.py` fingerprints table contents as well as row count/latest
time. `backtest/run_backtest.py` reuses it for feature cache identity. This catches
same-timestamp candle/feature corrections. Additional cache algorithm/stream
identity changes are **partially implemented** in the unfinished review fixes.

Report: `log/phase13-evaluation-report.md`.
